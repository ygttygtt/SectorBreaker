# SectorBreaker 领域破壁

**用 AI 在 1 小时内进入一个陌生领域，搭建可持续更新的行业认知系统。**

## 为什么做这个

很多人高估了信息的重要性，却低估了结构的重要性。

进入陌生领域时，大部分人的做法是：刷报告、搜平台、问朋友、收藏链接。几天后脑子里还是乱的——不知道行业怎么赚钱，谁是头部玩家，用户为什么买单，机会到底在哪里。

用 Gemini、GPT 的专家模式调研一个行业，它们会给你一篇几千字的"行业分析报告"。看完很爽，过几天就忘。因为你得到的是**信息**，而不是**系统**。

SectorBreaker 要解决的不是"生成一篇报告"，而是帮你快速打破信息差，把零散的信息整理成一套**可持续沉淀、可追溯证据、可导入 Obsidian** 的领域认知系统。研究完之后，你知道的不只是"这个行业怎么样"，而是：

- 应该先学什么，后学什么；
- 行业边界和常见误区是什么；
- 市场现状大概如何，数据口径怎么区分；
- 谁是玩家，谁掌握用户、渠道、资源和交付；
- 用户真正付钱购买的交易单位是什么；
- 内容、渠道、关键词和信任资产如何影响转化；
- 哪里可能存在需求、机会和风险；
- 哪些结论有证据，哪些只是待验证假设。

## 方法论：五步破壁

SectorBreaker 的研究流程来自一套系统化的行业认知方法，核心思路是：**先搭结构，再补事实，然后拆解交易单位、用户痛点、竞品结构、内容生态、监管边界和变化信号。**

### 第一步：建立行业数据库

不问观点，先建结构。

大部分人使用 AI 的方式是问一个问题、得到一个答案就结束。SectorBreaker 反过来——先帮你建立一个可持续填充的行业数据库：市场数据库、玩家数据库、交易单位数据库。

关键不是目录长什么样，而是**先把散乱的信息变成可填充的结构**。不同行业的目录自然不同：跨境电商要拆分平台、品类、供应链、履约和利润模型；养老行业要拆分用户、机构、支付方、政策和服务场景。

同时，SectorBreaker 会在一开始就帮你区分**数据口径**——陌生领域最容易踩的坑不是没有数据，而是把不同口径的数据混在一起，把局部趋势误认为整个行业的趋势。

### 第二步：反向拆解这个行业怎么赚钱

不写公司介绍，拆商业结构。

最快进入一个行业的方法永远是先拆同行，因为同行已经替你交过了学费。SectorBreaker 不会简单地"介绍某家公司"（那只是官网文案改写），而是拆解：**这家公司如何获客、如何建立信任、如何定价、如何成交、如何复购。**

拆解维度包括：

- **竞品数据库**：定位、目标用户、价格结构、获客渠道、转化路径、信任资产、复购机制、内容策略。
- **收入结构**：引流产品、转化产品、利润产品、复购产品——每一类的用户心理、价格区间和常见风险。
- **转化路径**：从用户第一次看到内容，到最终成交的完整链路。
- **信任资产**：用户最担心什么、凭什么相信你、哪些证据最有说服力。
- **价格、关键词和渠道**：用户在哪里搜索、搜索什么、搜索之后怎么被转化——一张**用户决策地图**。

### 第三步：研究内容生态

内容不只是娱乐，它是用户需求的公开样本库。

研究行业不能只看产品、公司、融资和政策。在今天，**内容本身就是生产资料**，因为它决定了用户怎么搜索、咨询、比较和成交。

SectorBreaker 会帮你批量整理内容账号、分析高频选题、给内容分类（曝光型、信任型、收藏型、转化型、案例型、专家 IP 型），找出用户最真实的决策障碍。

> SectorBreaker 在未接入第三方工具前无法直接爬取平台数据，但提供了**人为输入资料的窗口**——你可以把链接、截图、评论样本、主页文案粘贴进来，让 SectorBreaker 整理成结构化数据。

### 第四步：建立领域知识地图

碎片永远无法形成认知。数据库解决存储，地图解决理解。

把复杂领域画成一张图，所有信息才有位置。SectorBreaker 会帮你拆解行业地图（一级、二级、三级目录），区分供给侧和需求侧、渠道和交易单位、监管和风险边界，然后生成 Obsidian 知识卡片，为你定制一条高效的**入局路径**。

最后基于所有研究成果建立**机会地图**——不是空泛的趋势，而是可以继续验证的**假设**：机会逻辑、目标用户、进入门槛、需要的资源、主要风险、第一周可以验证什么。

### 第五步：让数据持续成长

行业是动态变化的，真正重要的不是建立一次性的数据库，而是**让数据库持续成长**。

从搜索模式切换到订阅模式：先建立信息源，持续接收，自动整理，定期复盘。竞品周报、内容监控周报、行业综合周报——每天有新内容进入，每周有新总结产生，每月有新机会浮现。

最终的结构：

```
Industry OS (行业操作系统)
├── Database (基础数据库)
├── Knowledge Map (知识地图)
├── Competitor Reports (竞品分析)
├── Content Reports (内容生态)
└── Monitoring (动态机会监控)
    └── Weekly Reviews (定期复盘)
```

## 产品形态

SectorBreaker 首版定位为**本地个人研究工作台**。

不是团队 SaaS，不是一次性 Prompt 工具。核心是把研究流程、Agent 分工、证据结构、知识库导出和项目问答打通。

### 工作流程

```
输入领域 → 范围确认 → 证据收集 → 研究框架 → 知识地图 → 机会地图 → 导出
  Landing    Gate 1     Gate 2     Gate 3     Gate 4     Gate 5    Gate 6
```

每个 Gate 完成后，用户可以：

- 查看 AI 的研究产出
- 补充自己已有的信息和数据（注入到 AI 的研究流程中）
- 添加研究方向备注（影响 AI 下一步的研究重点）
- 确认继续或跳过

### 技术架构

- **LangGraph** — 多 Agent 编排框架，6 个固定 Gate + 动态 Supervisor
- **FastAPI** — 后端 API，SSE 事件流
- **Vite + React + TypeScript** — 前端工作台，GSAP 动画
- **SQLite + FTS** — 本地结构化存储与全文检索
- **Obsidian** — 知识库输出格式（Markdown）

### Agent 分工

| Agent | 职责 |
|-------|------|
| Research Planner | 生成研究框架、关键问题、学习路径 |
| Search Scout | 查询外部搜索来源 |
| Evidence Curator | 归一化来源、置信度标注、冲突标记 |
| Market Mapper | 市场规模、增长驱动、限制因素 |
| Player Analyst | 玩家角色、议价能力、商业模式 |
| Transaction Analyst | 交易单位、定价、频率、风险、毛利 |
| Content Channel Analyst | 内容生态、渠道、关键词、转化路径 |
| Knowledge Mapper | 行业地图、知识卡片、节点关系 |
| Opportunity Analyst | 机会假设、验证路径、风险评估 |
| QA Critic | 质量检查、证据完整性、覆盖率 |
| Export Writer | Markdown/Obsidian 导出 |

## 快速开始

详见 [docs/quickstart.md](docs/quickstart.md)。

```bash
# 环境准备
conda env create -f environment.yml
conda activate sectorbreaker
cd frontend && npm install

# 启动（两个终端）
# 终端 1：python -m uvicorn backend.app.api.app:app --port 8030 --reload
# 终端 2：cd frontend && npm run dev

# 打开 http://127.0.0.1:5173/
```

## 协作规则

这是一个多人、多 Agent 接力开发项目。任何贡献者或 Agent 在动手前应先读：

1. `AGENTS.md`
2. `CLAUDE.md`
3. `docs/10-current-status-and-handoff.md`
4. `docs/11-tooling-handoff.md`
5. 与自己任务相关的 `docs/0x-*.md`

核心原则：

- 文档先行、schema 先行、测试先行、证据先行。
- Agent 输出必须结构化，不能只交换散文。
- 外部能力必须通过 provider 接口。
- 关键研究结论必须关联 evidence id。
- 提交日志统一使用中文。
