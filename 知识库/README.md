## 统一项目口径

SectorBreaker 是一套面向陌生领域研究和长期知识维护的高自治 Multi-Agent 系统。它既可以从一个领域目标启动研究，也可以接管已有 Markdown/Obsidian Vault。Master Agent 围绕持久化 State 自主选择检索、联网搜索、资料读取、Specialist 委派、覆盖评估、知识写作、修改提案、人工确认或停止；系统通过 Evidence、Artifact Revision、ChangeSet、Diff、审批和回滚控制知识库演化。

项目不是一次性 Deep Search 报告生成器，也不是把 L1-L5 写成固定节点的传统 Workflow。当前生产执行 Owner 是自研 Agent Kernel：

```text
backend.app.agent_kernel.run_v2_agent_kernel_pipeline
```

函数名保留了 V2 兼容命名，但当前 State、知识控制面和导出协议均为 V3。

## 关于“本地优先”和“已经上线”

两者并不冲突：

- “本地优先”描述的是数据和部署边界。知识原文、SQLite、向量索引、模型缓存和导出 Vault 可以在用户私有环境内运行，不强制依赖平台托管数据库。
- 线上产品版本已经部署，后端统一运行在阿里云服务器上。这是项目作者提供的真实产品事实。
- 当前产品定位仍是单用户或私有化知识工作台，不应包装成已经完成多租户、高并发和组织权限体系的 SaaS。

## 事实来源分级

本知识库中的表述分三类：

- `简历事实`：来自《王天艺_Agent开发工程师_2年经验.pdf》中 SectorBreaker 项目描述。
- `仓库事实`：可由当前代码、测试和项目文档直接验证。
- `部署事实`：由项目作者明确补充，例如“产品已上线，后端位于阿里云服务器”。

如果某个线上参数没有出现在代码或简历中，例如 ECS 规格、QPS、域名、网关品牌、监控平台，不会被擅自编造成已实现事实。

## 一句话版本

> SectorBreaker 是一个以 State 驱动的高自治知识管理 Agent：Master Agent 在受控工具和预算内动态研究、验证和维护知识，Specialist Agent 按需并发协作，所有事实和知识修改都通过证据、版本、Diff、审批和回滚形成可追溯闭环，最终输出可持续演化的 Obsidian 知识库。
