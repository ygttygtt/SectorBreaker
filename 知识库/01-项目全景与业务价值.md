# 项目全景与业务价值

## 项目要解决什么问题

传统 Deep Search 或普通聊天机器人通常完成一次问答或生成一篇报告。主要问题是：

- 研究过程和结论没有稳定的结构化 State；
- 下一次追问很难知道之前查过什么、哪些来源可信、哪些问题还没解决；
- 生成文本和原始证据脱节；
- 修改知识时通常直接覆盖，缺少审批、Diff 和回滚；
- 一次性报告不容易沉淀为长期可检索、可维护的个人知识资产。

SectorBreaker 把问题重新定义为“知识生命周期管理”：

```text
创建或接管知识库
  -> 发现结构/事实缺口
  -> 形成维护任务
  -> Agent 研究和验证
  -> 创建或提出知识修改
  -> 审批应用
  -> 版本化导出
  -> 后续追问继续生长
```

## 两类核心用户旅程

### 从零研究一个陌生领域

用户输入领域、目标、研究深度和来源策略。系统创建自适应 Knowledge Schema，Master Agent 读取当前覆盖度和开放问题，自主决定先读用户资料、检索项目记忆、联网搜索、验证证据、写主文档、补解释卡或生成导航页。最终输出 Obsidian Vault。

### 接管和维护已有知识库

用户导入 Markdown/Obsidian Vault。系统不直接修改源目录，而是导入受管镜像：

1. 保留相对路径和内容 Hash；
2. 确定性检查断链、孤立笔记、重复标题、缺失 Front Matter、缺失证据元数据和 TODO；
3. 生成去重的 Maintenance Backlog；
4. Agent 选择任务并研究；
5. 修改已有知识时生成 ChangeSet、Base Hash 和 Unified Diff；
6. 审批后生成新 Artifact Revision；
7. 可以导出或回滚。

## 为什么输出选择 Obsidian/Markdown

- Markdown 是人类可读的开放格式，不被平台锁定；
- Obsidian 的 Wikilink、Backlink、Folder 和 Front Matter 适合构建第二大脑；
- Agent 可以对单篇笔记做最小范围修改，而不是每次重写长报告；
- Git、Diff、Hash 和全文检索生态成熟；
- 即使 SectorBreaker 服务暂时不可用，用户仍能直接打开知识文件。

## 产品差异化

### 与普通 RAG 问答的区别

RAG 解决“从已有资料中召回上下文并回答”。SectorBreaker 还管理：

- 哪些知识已经覆盖；
- 哪些 Claim 有证据；
- 哪些问题需要继续研究；
- 哪些 Artifact 是 Active Revision；
- 哪些修改等待审批；
- 哪些历史版本可以回滚；
- Agent 是否拥有执行某种修改的权限。

### 与固定 Workflow 的区别

固定 Workflow 预先规定“搜索 -> 总结 -> 写作 -> 导出”。SectorBreaker 的 Master Agent 每轮根据 State 决定下一步，可能：

- 先读上传报告，再减少重复搜索；
- 在证据不足时改变搜索问题；
- 委派 Verifier 而不是继续泛搜；
- 发现新术语后创建 Drill-down Question；
- 某层信息只有 Partial Evidence 时先写带待验证项的初版；
- 更新已有笔记时暂停等待用户审批；
- 连续失败时 Block，而不是输出模板假装成功。

### 与一次性报告的区别

一次性报告是“最终文本”。SectorBreaker 的结果是“知识资产 + 控制面状态”：

```text
Markdown/Obsidian 知识页面
Evidence Ledger
Artifact Manifest
Agent State
Health Snapshot
Maintenance Backlog
ChangeSet History
Open Questions
Trace Summary
```

## 业务价值怎么回答

可以从四个层面回答：

1. 研究效率：把资料搜集、正文抽取、去重、结构化整理、覆盖判断和知识写作串成闭环。
2. 结果可信度：重要事实保留 Evidence ID、来源质量、验证状态和冲突信息。
3. 知识复用：知识不是聊天记录，而是可检索、可链接、可持续更新的 Vault。
4. 变更安全：已有知识不能被 Agent 静默覆盖，必须经过 Diff、Base Hash、权限和审批。

## 已上线产品的准确口径

SectorBreaker 已经作为产品上线，后端部署在阿里云服务器。当前架构强调 Local-first 和 Private-first，意味着它可以部署在用户私有环境或单租户服务器上，核心知识和索引不强制上传到平台托管数据库。

面试中应把它描述为“已上线的单用户/私有化知识工作台产品”，而不是“只能在开发机运行的 Demo”；同时也不要把它说成已经完成多租户、组织权限、海量并发的公有云 SaaS。

## 30 秒项目介绍

> SectorBreaker 是我负责核心开发和 Agent 架构设计的高自治 Multi-Agent 知识管理系统。它不是固定搜索写报告，而是由 Master Agent 围绕持久 State 动态选择检索、搜索、委派审计/研究/验证/编辑 Specialist、生成知识或等待人工确认。系统用本地 Hybrid RAG 统一检索 Evidence、上传资料和 Active Artifact，用 Evidence、ChangeSet、Base Hash、不可变 Revision 和 Rollback 控制知识可信度与修改安全，最终输出可直接打开的 Obsidian Vault。产品已经上线，后端运行在阿里云服务器。
