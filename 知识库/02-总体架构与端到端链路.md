# 总体架构与端到端链路

## 分层架构

SectorBreaker 可以拆成七层：

1. 交互层：React + TypeScript 工作台。
2. API 层：FastAPI + Pydantic 强类型接口。
3. Agent Kernel：Master Agent 决策循环、预算、工具分发、Observation 和 State Reducer。
4. Specialist 层：审计、研究、验证和知识编辑的任务级委派。
5. 知识控制面：Vault Audit、Maintenance Task、ChangeSet、Approval、Revision、Rollback。
6. Retrieval/Evidence 层：SQLite FTS、本地 Embedding、向量索引、RRF、Web Search、正文抽取和来源评估。
7. 持久化与导出层：SQLite 结构化状态 + Markdown/Obsidian 人类可读知识库。

```text
React Workbench
    |
    v
FastAPI / Pydantic API
    |
    +--> Run / SSE / Resume / Recover
    |
    v
Master Agent Kernel
    |-- ContextPack + ArtifactMemory + Budget
    |-- Tool Registry
    |-- Specialist Delegation
    |-- Observation -> StateDelta -> Reducer
    |
    +--> ProjectRetriever
    |      |-- Lexical candidates
    |      |-- Local vector candidates
    |      `-- RRF fusion
    |
    +--> Search / Extraction / Verification Providers
    |
    +--> Vault / ChangeSet / Artifact Revision Services
    |
    v
SQLite + Managed Markdown/Obsidian Export
```

## 生产入口

唯一生产执行 Owner：

```python
backend.app.agent_kernel.run_v2_agent_kernel_pipeline
```

名字中的 V2 是迁移兼容遗留，不能据此说当前还是 V2 数据协议。Pipeline 初始化的 State Version 是 `3`，Artifact Schema 是 `v3-knowledge-ops`。

## Bootstrap 端到端链路

### 1. 创建 Project

Project 保存：领域、市场范围、深度、Source Policy 和 Source Preferences。Source Preferences 包含 Source Pack、Custom Allowed Domains、Blocked Domains 以及 `prefer/require` Enforcement。

### 2. 初始化自适应 Knowledge Schema

Pipeline 调用 `build_adaptive_schema()`。默认认知锚点可以包含：

- L0 前置扫盲；
- L1 本源与需求；
- L2 角色与玩家；
- L3 原理与实操；
- L4 商业与激励；
- L5 风险与边界。

这些是认知结构，不是固定执行节点。Agent 可以跳层、回到前置问题、并行补卡或提前进入验证。

### 3. 内化用户资料

在联网搜索前，`ReportInternalizer` 读取上传资料或 Resume 时的 Assistant Brief，抽取 Claim、Entity、Open Question 等内容进入 State。外部 AI 报告默认低可信，只作为上下文和搜索线索，不会直接变成 Verified Evidence。

### 4. 构建 Agent Context

每轮决策只给 LLM 有界上下文：

- Meta Context；
- Knowledge Schema 和 Coverage；
- 过滤后的 ContextPack；
- Active Artifact 摘要；
- Vault/Health/Backlog/Autonomy Policy；
- 可用 Tool Schema；
- 最近十条 Trace。

这样避免直接把整个数据库、所有正文和完整日志塞入 Prompt。

### 5. Master Agent 决策

LLM 返回 Pydantic `AgentDecision`，包含：

- Thought Summary；
- User Notice；
- Action Type；
- 一个或多个 Tool Call；
- Current Goal；
- Plan Steps；
- Progress Check；
- Expected Observation；
- Stop Reason。

### 6. 工具执行与观察

Tool Registry 根据工具名分发处理函数。每个工具返回统一的 `KernelObservation`：成功与否、摘要、Data、StateDelta、Evidence IDs、Artifact IDs、是否需要人工，以及 Error。

### 7. Reducer 更新 State

Reducer 负责：

- Source/Entity/Relationship/Open Question 去重；
- Claim 合并、冲突和 Supersede；
- 未知 Evidence 的 Verified Claim 降级；
- Coverage 更新；
- Memory hide/delete/resolve；
- Decision Log 追加。

### 8. Artifact 写入和 Checkpoint

成功生成 Artifact 时，先持久化 Artifact，再保存引用它的 `artifact_write` checkpoint，避免出现“Checkpoint 声称可恢复，但 Artifact 还没落盘”的不一致。

### 9. Finish Gate

历史 Artifact 不能满足本轮完成条件。本轮必须有新 Artifact，或恢复后的同一 Run 已经生成归属于该 Run 的 Artifact，否则 `finish` 会被阻断为 `finish_without_run_output`。

## Existing Vault 维护链路

```text
Vault Import
  -> Snapshot Hash / Artifact Revision
  -> Deterministic Audit
  -> Stable Maintenance Backlog
  -> Maintenance Run
  -> Retrieve / Search / Specialist
  -> ChangeSet Proposal
  -> Human Approval
  -> Apply New Revision
  -> Resume Same Run
  -> Export or Rollback
```

重要边界：源 Vault 只读。SectorBreaker 写的是受管 Artifact Revision 和导出 Vault，不会在第一版中直接破坏用户原目录。

## 为什么同时使用 SQLite 和 Markdown

SQLite 适合保存：

- Project、Run、Event、Checkpoint；
- Evidence、Document、Segment；
- Artifact Revision 关系；
- Vault Import、Health Report、Maintenance Task、ChangeSet；
- 本地向量索引。

Markdown 适合保存：

- 最终可阅读知识；
- Obsidian 链接和 Front Matter；
- 用户可以脱离系统继续使用的知识资产。

SQLite 是控制面和结构化真相，Markdown 是人类知识表面。Vector Index 是可重建派生数据，不是唯一真相源。
