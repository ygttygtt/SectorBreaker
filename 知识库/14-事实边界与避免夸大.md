# 事实边界与避免夸大

## 可以明确说的

- 产品已经上线，后端运行在阿里云服务器。
- 当前生产核心是 Custom Agent Kernel。
- Master Agent 根据 State 动态选择工具和停止条件。
- 有四类 Specialist，可最多四任务并发。
- Specialist 有角色 Tool Allowlist，不能直接 Apply。
- 有真实 Local Hybrid RAG，不是纯关键词伪装。
- FastEmbed 默认模型是 `BAAI/bge-small-zh-v1.5`。
- 使用 SQLite FTS + SQLite Vector Index + RRF。
- 有 Evidence ID、Source Quality、Verification Status 和 Extraction Metadata。
- 有 Immutable Artifact Revision、ChangeSet、Diff、Base Hash、Approval 和 Rollback。
- 有 SSE、Heartbeat、Checkpoint、Resume、Recover 和 Run Lease。
- 真实跑通过 LLM + Tavily + HTTP Extraction 的端到端验收。

## 必须带边界说的

### Multi-Agent

正确：Master 动态委派 Typed Specialist，并发分析和返回建议。

边界：Specialist 还没有独立多轮 ReAct 和 Per-task External Tool Dispatcher。

### Evidence Verification

正确：ID 真实性、Project Ownership 和 Factual Change Evidence Gate 已实现。

边界：Claim 文本与 Evidence 正文的语义支持校验还不完整。

### Online Product

正确：已经上线，后端在阿里云。

边界：当前是单用户/私有化工作台，不是已完成多租户高并发 SaaS。

### Local-first

正确：数据和模型可在私有环境运行。

边界：不是完全不联网；在 Policy 允许时会调用 LLM、Search 和 Extraction Provider。

### Coverage

正确：有工程化 Coverage Score 和 Ready-to-write。

边界：不是严格学习出来的质量模型，也不能单凭 Score 证明内容正确。

- “SectorBreaker 已实现 Cross-Encoder Reranker。”
- “所有 Claim 都经过 NLI 自动验证。”
- “每个 Specialist 都是独立完整 ReAct Agent。”
- “已经支持 Kubernetes、微服务、自动扩缩容。”
- “已经支持多租户、组织权限和高并发。”
- “已经支持双向实时同步用户源 Vault。”
- “已经支持自动定时监控和后台刷新。”
- “支持 Move/Delete 笔记自动执行。”
- “Firecrawl Map/Crawl 已接入生产 Agent。”
- “所有搜索 Provider 在当前线上都配置可用。”
- “LangGraph 是当前固定生产流程核心。”
- “旧 L1-L5 Pipeline 仍是当前产品路径。”

## 不要把其他项目指标混进来

简历中“首批 12 节课程评测集所有问题 Top-5 命中”属于 SideWing 项目，不属于 SectorBreaker。

“Cross-Encoder Reranker、pgvector”也是 SideWing 或个人通用 RAG 能力，不是 SectorBreaker 当前仓库实现。

SectorBreaker 可以使用的数字：

- 历史测试基线 254 Backend / 32 Frontend；
- 真实验收 42 条 Search Evidence；
- 4 个 Active V3 Artifact；
- 真实 Run 约 10 分钟；
- 最多 4 个 Specialist Task 并发；
- 默认 Agent Budget 根据 Depth 为 Quick/Standard/Deep 三档；
- 默认 Chunk 约 1400 字符、Overlap 180；
- 默认 RRF k=60；
- FastEmbed 实际模型维度 512。

使用数字时说明上下文，不把单次验收说成稳定线上 SLA。

## 简历表述与当前代码有差异时怎么说

> 简历描述的是产品能力和我负责的架构范围，仓库是当前本地优先版本的可验证实现。线上部署配置没有全部公开进仓库，但产品确实已经上线，后端在阿里云。对于代码中还处于演进阶段的能力，我会明确区分已实现、部分实现和规划，不会用目标架构冒充当前现状。

## 被问到“你是不是包装项目”时

可以用证据回答：

- 指出生产入口和 Runtime Loop；
- 说出 AgentDecision/Observation/StateDelta 模型；
- 解释 Artifact-first Checkpoint；
- 解释 Base Hash Conflict；
- 解释 RRF 和 Content Hash Incremental Index；
- 解释 Provider Fan-out Budget；
- 解释 Resume 与 Recover 的不同；
- 给出真实验收的 Evidence/Artifact/ChangeSet 数字；
- 主动承认 Claim-level Semantic Verification 和 Specialist Nested ReAct 尚未完成。

能说清具体数据结构、失败分支和取舍，通常比堆叠框架名更能证明真实经历。
